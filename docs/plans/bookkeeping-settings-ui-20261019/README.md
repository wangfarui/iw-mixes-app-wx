## 5. 产品交互规格

### 5.1 首页

原生标题“记账设置”。内容为一个圆角列表分组，顺序固定：

| 名称 | 副标题 | 类型/现有页面 |
|---|---|---|
| 记账分类 | 整理每笔账单的用途分类 | `CATEGORY` / `bookkeeping-category-settings` |
| 支出标签 | 标记外卖、聚餐等支出场景 | `EXPENSE_TAG` / `bookkeeping-consume-tag-settings` |
| 收入标签 | 标记工资、返现等收入来源 | `INCOME_TAG` / `bookkeeping-income-tag-settings` |

统一浅绿色图标底、清晰主副标题、右侧箭头，整行点击；不加数量接口请求。分组下方轻量说明：“改名、停用或删除选项后，已有账单仍保留原来的名称。” 首页不设置个人/家庭切换，也没有底部新增按钮。

### 5.2 三个管理页

- 有家庭：顶部“我的 / 家庭共用”分段切换；无家庭：隐藏切换，仅个人范围。
- 个人说明：“仅自己管理，可用于个人或共享账单”；家庭可管理说明：“家庭成员均可使用，群主和家长可管理”；只读说明：“家庭共用选项 · 当前仅可查看”。
- 启用区标题“已启用 · N 项”，有权限时右侧“排序”。每行只有名称和“更多”；点击名称打开改名。
- 停用项数量大于 0 才显示折叠入口；展开为独立列表，标注“已停用”，不能与启用项混在一起造成状态不明。
- 管理者底部主按钮“新增分类”或“新增标签”。家庭范围另有“从我的选项添加”。只读时两项都隐藏，行名也不可编辑。
- `canManage` 以服务端响应为准；不通过用户名、硬编码角色或前端缓存擅自授予管理能力。
- loading、列表为空、请求失败需区分。加载失败不能显示成“暂无选项”；失败页有重试，首次加载完成前不展示可写按钮。

### 5.3 新增/改名底部表单

- 标题按动作/类型生成；显式“分类名称/标签名称”标签，placeholder 给对应示例，不能只靠 placeholder 说明字段。
- 输入区完整边框、背景和稳定高度；显示规范化后的字符数及 32 上限，就地呈现空白、超长、同范围重名错误。
- 使用现有 Unicode 首尾空白规范化；长度按码点计算，支持 emoji。内部空格、大小写、重音不自动改写；不按 JS `length` 或原生 `maxlength=32` 截断合法输入。当前 `maxlength=-1` 可保留，由校验控制保存。
- 保留用户输入的原始草稿，规范化只用于派生校验/提交；不要在每次 bindinput 时重写文本、重设光标或重复 focus，尤其不能打断中文输入法组合。异步刷新列表不重建正在编辑的 input。
- 空值/重名/超长时禁用保存；提交中显示 loading，保存、取消、关闭均禁止重复触发。改名时不改名称可按无操作关闭，或沿现有接口处理；不要制造新 ID。
- 点击取消/关闭明确结束；编辑表单不通过点击遮罩直接丢弃已输入内容。关闭时收起键盘，清理该弹层状态。
- 普通写入失败保留输入及表单，不关闭/假成功；恢复可重试。错误信息以服务端为准，页面可显示 `error.message`，避免与请求层重复连续 toast。
- 写成功后只请求一次写 API，失效候选缓存，再更新/刷新列表。若随后列表刷新失败，明确“已保存，列表刷新失败”，提供只读重试，不能再次 POST 同一个新增请求。
- 改名提示：“修改后，已有账单仍保留原来的名称。” 改名成功必须接受新 ID/revision，不能沿用旧 ID 发起后续启停/删除。

### 5.4 更多操作与删除

底部菜单标题为完整选项名；动作依次为“修改名称”“停用/启用分类（标签）”“删除分类（标签）”。长名称可换行，不挤出关闭按钮。更多菜单和编辑表单互斥，不叠两层遮罩。

删除进入二次确认，说明“已有账单保留原名称，之后记账将不再提供此选项”，删除按钮用克制的危险色。取消不发送请求。启停/删除带打开时的 `id + revision`；服务端冲突后刷新权威数据，不自动改用新 revision 再执行一次。

### 5.5 排序

- 点“排序”进入独立模式：保存一份全量原始顺序，生成独立排序草稿；展开当前范围全部项，包含停用项并标注状态。
- 展示手柄及上移/下移；首尾边界按钮禁用。拖动和按钮共用同一重排计算。
- 排序中隐藏新增、复制、普通更多菜单及停用折叠，禁止切换范围；提供“取消 / 完成”。
- 取消只恢复本地原始顺序，不调用排序 API。返回上一页视为放弃未提交排序；不能因为 onShow/onHide 刷新而意外提交。
- 完成提交**全部当前项 ID**（各出现一次）和进入排序时取得的 `scopeVersion`，不能只提交启用区/可见区 ID。
- 写入失败可保留草稿重试；版本冲突不能无限重试旧 payload：明确提示并重新加载，要求基于新列表重新排序。
- 提交中阻止拖动、取消及重复完成。成功后缓存失效并加载新 scopeVersion；保持当前范围。

### 5.6 家庭复制

- 仅家庭范围且 `canManage=true` 可进入，读取当前类型的本人个人项。候选加载前不能提交。
- 多选有“添加所选（N）”；0 项时禁用。重复姓名项标“已存在”且不可选；家庭已停用同名项也占名，不允许通过复制自动启用。
- **个人已停用项仍是合法可复制来源**：显示“已停用”，保持可选；后端会复制其停用状态。不要为 UI 简化而静默过滤或改为启用。
- 仅提交选中的 `sourceIds`；不由前端指定别人的用户 ID 或家庭 ID，不修改个人原项。
- 成功结果按服务端 `created[] / skipped[]` 显示数量；提交期间新发生的重名仍可能被服务端跳过，不能只凭前端勾选数宣称全部成功。
- 网络失败保留勾选并可重试；身份/家庭已变时关闭弹层、清空勾选并加载新范围，禁止将旧家庭请求套用到新家庭。

## 6. 视觉尺寸与原生实现要点

以下数值是 375px 设计稿的起点，落地使用 rpx/px 时须区分用途；最终以原生实测无裁切、无遮挡为准。

| 元素 | 建议起点 |
|---|---|
| 页面左右内边距 | 32rpx |
| 背景/分组 | 轻灰页面、白色列表分组；绿色仅用于主操作/选中态 |
| 首页入口 | 最小约 168–176rpx；图标底约 84rpx，图标约 40–44rpx |
| 主文字/副文字 | 32rpx / 24rpx；名称正常换行，不缩小字号塞进按钮旁 |
| 普通列表行 | 最小 112–120rpx，高度可随长名称增大 |
| 行尾及关闭等触摸区 | 375px稿约 88rpx × 88rpx；用最小 44px 逻辑触摸区兜底，不能随窄屏缩成小按钮 |
| 列表/主按钮/弹层圆角 | 约 24–32rpx / 24rpx / 顶部 40–44rpx |
| 主按钮 | 高约 92rpx；文字垂直/水平居中，不换行 |
| 输入外框 | 推荐稳定逻辑高度 54px；内部 input 高/行高 24px，字号 16px（对应375px稿108/48/32rpx） |
| 页底及弹层 | 内容留白 + 单次安全区补偿；家庭双操作的内容占位要大于个人单操作 |

### 6.1 输入框与全局样式冲突

项目 `app.wxss` 全局设置了 `input/button` 等 `box-sizing:border-box`，并加载 WeUI。不要再给原生 input 直接堆垂直 padding、边框和不确定的默认高度。

推荐外层 view 负责固定高度、边框、圆角、水平 padding 和居中；内部 input 独立设置明确高度、行高、字号，垂直 padding 为 0。placeholder 使用同一字体尺寸并实际观察光标/中文/英文/emoji。页面按钮局部定义 margin、padding、line-height、display 对齐，不全局覆盖 WeUI。

首页图标优先复用能匹配定稿的本地资源；缺少时在本模块增加小型 PNG。不要把原型依赖的 DOM/Lucide CDN/HTML 按钮或 emoji 图标搬入小程序；不要为了三枚图标重做全局 iconfont。

### 6.2 键盘与安全区

- 推荐单一适配模型：编辑 input 关闭系统自动顶起，页面按真实键盘高度调整 sheet 的 bottom（**px**），避免再叠加系统顶起造成双重位移。
- 输入组件键盘高度事件优先作为局部来源；如需页面级监听，能力检测并保存同一个监听引用，onHide/onUnload 移除，onShow 重入不能重复注册。新会话须用项目当前基础库/工具确认事件表现，不能以浏览器占位图代替。
- 记录键盘未弹起时的窗口高度作为布局基准。不能从已经缩小的 windowHeight 再减一次键盘高度；旋转/窗口宽度变化后重新测量。
- 弹层最大可用高度需扣除原生导航区域、顶部留白及实际键盘区域；内容过长时表单内容可滚动，保存/取消保持可达。
- 键盘收起时补底部安全区；键盘弹起时避免再叠一份 Home Indicator 安全区。不要同时使用计算出的 safeBottom 和 `env(safe-area-inset-bottom)` 重复加高。
- 页底单按钮/双按钮区测量或明确计算高度，为正文预留相应空间；展开停用列表、长名称换行后仍不能盖住最后一行。
- 遮罩拦截背景点击/滚动，但不得把弹层内复制列表的 scroll-view 一起禁滚；背景锁滚与弹层滚动分别验证。

### 6.3 原生长列表拖动排序

在现有共享页面工厂中实现，不引入第三方拖动库：

1. 只在排序模式测量每行真实矩形，缓存到实例字段；长名称会使行高变化，不能用固定行高简单除位移算目标位置。
2. 手柄长按进入拖动；保留原行占位，使用浮层/拖动影子跟随，普通行区域仍可正常纵向滚动。
3. 坐标统一使用同一坐标系，考虑页面滚动位移；按相邻行中心线判断插入位置。只在跨越目标行时更新顺序。
4. 接近可视区域上下边缘时进行受限自动滚动；滚动后重算位置，保证超过一屏时仍可从首部移动到底部。不要通过高频全列表 setData 或硬编码 CSS 动画掩盖位置错误。
5. 手势结束、取消、页面隐藏、切账号和失去权限都清理浮层、定时器、坐标缓存及拖动状态；不能在弹层打开后继续收到旧拖动事件。
6. 上移/下移继续可用，但只支持按钮、未实现或未实测拖动，不能声明已满足定稿方案。

## 7. 建议的共享状态与异步边界

继续使用当前“共享 JS 工厂 + WXML 模板 + WXSS”结构。无需为了本次页面另建通用设置平台。

| 状态组 | 建议职责 |
|---|---|
| 领域 | `type`、类型文案、`scope`、`hasFamily`、`canManage`、`items`、`scopeVersion` |
| 列表派生 | `enabledItems`、`disabledItems`、数量、`showDisabled`；不将派生数组当权威全量列表 |
| 加载 | `loading`、`loadError`；首次与保留旧数据的轻量刷新可区分 |
| 弹层 | 单一 `activeSheet: none/editor/menu/delete/copy`，避免多个布尔量造成双重遮罩 |
| 编辑 | `editingItem`、`draftName`、规范化值、`nameCount`、`nameError`、`canSave` |
| 写入 | `busy` / 具体操作名、写入是否已成功；页面点击和方法入口双重防重 |
| 排序 | 原始顺序/全量草稿 ID、进入时的版本、拖动项；原始快照独立存储 |
| 复制 | 加载状态、派生重复/停用标记、选中 ID、数量及可提交状态 |
| 布局 | 键盘高度 px、可用高度、页底高度；不把每次 touchmove 的全部中间数据放进 data |
| 实例私有 | 请求序号、视图上下文代数、身份 key、监听引用、拖动坐标/计时器、disposed 标记 |

请求上下文至少包含：`type + scope + 用户/会话身份 + familyGroupId + 请求序号`。复用 `optionsStore.identity()` 作内存比较，**禁止打印该值，因为包含 token**。

必须处理：

- A 范围的慢响应晚于 B 范围返回时，不能覆盖 B；copy/read/write 后续刷新也一样。
- 写请求发送后切账号、退群或销毁页面，回包不能关闭新页面表单、弹出跨身份成功提示或刷新新身份列表。不能取消已发送的服务端写入事实，但必须隔离其旧 UI 后续动作。
- revision/scopeVersion 冲突后刷新权威列表；保留仍属于当前身份/范围的名称草稿并标记需重新核对，不能偷偷替换版本继续写。失去权限时关闭写弹层并进入只读。
- onShow 重新确认家庭及列表；相同身份下普通刷新不应无故销毁正在输入的内容。发生身份/家庭变化则必须清除旧菜单、选中项、复制勾选和排序草稿。
- `load`、`openCopy` 等错误需要被页面捕获，不能只依赖请求层 toast 留下 unhandled rejection。
- 卸载/隐藏中解除监听，迟到 finally 不能把新请求的 busy/loading 状态清掉。可使用各操作自身的序号/上下文判断后再 setData。
