2. 保留 P00–P05 的全部结果。P01 必须为 `READY_MYSQL8`，P00 确认为目标生产库，才能执行 [01-data-quality.sql](01-data-quality.sql)。如果版本不是 MySQL 8、缺表或缺列，停止在第一份，把结果发回来，由我按实际结构调整。
3. 第二份在同一新查询连接中完整执行，包含只读事务与末尾 ROLLBACK。回传所有 P10–P21 的结果，保留 check_id 和列名。结果只包含统计数量，不查询衣物名称、图片、备注、账户、密码或 token。
4. 完成后关闭本次专用查询连接。如果执行中报错或超时，停止后续语句，记录报错与对应查询编号；仍在该连接时执行 `ROLLBACK;` 结束只读事务。不要添加 `--force`、修复语句或执行旧模板刷新脚本。

第二份查询按 MySQL 8 编写，每个主要 SELECT 设置10秒执行提示，不使用锁定读，不执行数据库数据/结构变更；只读事务仍会消耗查询资源，宜在业务空闲时运行。P02 的 table_rows 为引擎估算，P10 才是本次实际统计。若 P02 显示相关表体量很大，先只回传第一份，由我调整扫描范围和查询方案。

## 查询能回答什么

| 结果 | 用途 |
|---|---|
| P00–P05 | 目标库与MySQL版本、必要列、估算规模、当前字段/索引、是否已有快照结构 |
| P10–P12 | 实际业务规模、五类字典的模板/个人/家庭分布、业务所有者缺少个人类型的情况 |
| P13–P14 | 同范围重复编码、重复名称初筛、款式父项是否缺失或跨归属 |
| P15–P16 | 品类/款式旧码能找到个人来源、已删除来源或模板的比例，以及父品类不匹配情况 |
| P17–P18 | 标签是数字、英文、混合还是非规范数字；数字能否唯一关联原范围来源，是否有重复 token |
| P19 | 颜色文本能否精确找到来源，不依靠模糊匹配 |
| P20 | 明细对应衣物是否删除、当前所属人是否变化、主记录是否存在 |
| P21 | 是否有版本链与变更迹象；不能据此证明所有历史名称可还原 |

`deleted=0/1` 分别统计，避免只看活跃数据而漏掉历史快照。`current_owner_differs` 可能是正常转交，不直接视为脏数据。个人当前来源唯一，也只证明当前可解析，不能证明创建时名称；缺来源但模板唯一，也不能把模板ID直接当个人历史来源。

重复名称使用 SQL Unicode 空白初筛与二进制字节比较；完整迁移仍须与 Java 名称规范化保持一致，不因初筛为0就省略最终预检。款式重复名按父ID分组，是旧结构初筛，迁移后的稳定谱系唯一性另行核实。

本包不查询实际生产Nginx、发布版本或客户端版本。数据结果返回后先判断生产是否存在真实迁移歧义；确有需要再提供最多若干异常主键的定向查询，不要求导出业务表或提供数据库凭据。
