## 4. 定稿目标行为

### 4.1 管理交互

首页为两条紧凑列表，点击进入独立管理页。有家庭显示“我的 / 家庭共用”，无家庭只显示“我的”。每类支持新增、改名、启停、逻辑删除、排序；家庭管理者另有“从我的选项添加”。不展示code、同步所有用户等技术字段。

沿用衣柜最终布局：可滚动列表与页底操作栏各占布局空间，新增和复制按钮不遮挡最后一项；停用项折叠；改名/新增用底部表单；排序独立模式，支持拖动和上下移。

名称去首尾Unicode空白，1–32个码点；同类型同范围名称唯一，停用项也占用名称。个人与家庭同名可独立存在。食品分类与存放分区是两套独立平面字典，不引入衣柜品类/款式父子树。

加载、空列表、读取失败重试、只读、写入中均有明确状态。写入失败保留输入；写入成功但刷新失败提示已保存并只重试读取。离开未保存表单或排序时确认放弃；用户/家庭切换清理草稿并拒收迟到响应。版本冲突刷新后由用户重试，不盲目重放写请求。

### 4.2 个人、家庭与选用

- 已确认维护权限：个人字典仅本人维护；家庭变化不转移个人项所有权。
- 已确认家庭维护权限：有效成员使用；群主/家长可新增、改名、启停、删除、排序及从个人选项添加，普通成员/儿童只读和使用。所有写操作在服务端鉴权。
- 已确认首次初始化：家庭首次启用自动从系统两类模板填入默认选项，仅初始化一次；不自动公开成员私人字典；删空后不补回。群主/家长可通过“从我的选项添加”主动复制。
- 已整体确认复制细则：复制个人项产生独立家庭项，后续双方互不联动；家庭同名项包括停用项均跳过，不自动启用。
- 已确认：新增食材或主动重新选择分类/分区使用记录所属人的启用个人项 + 当前家庭启用共用项；同类型同名合并，个人优先；已有食材来源与名称不因候选合并而改变，管理页仍按范围独立维护。当前没有本轮确认的代录能力，不新增所属人切换。
- 若实施调查发现实际存在授权编辑他人食材的路径，选项须按记录真实所属人并先校验编辑权限；只读查看他人数据不能获取整套私人字典或获得写权。
- 入退家庭只影响之后的新选择，不修改旧记录来源和名称；字典共用不扩大食材本身的可见或可编辑范围。

### 4.3 名称与现有食材

已确认业务行为：改名、停用或删除后保留已有食材的分类/分区原名，主动重新选择才更新；无关字段编辑不刷新快照。

工程建议沿用衣柜：改名产生后继版本，记录旧来源；启停与排序不换ID，删除为逻辑删除。食材保存分类/分区的来源ID与名称快照，名称由服务端从可信来源生成，客户端不能自报名称。旧编码列保留追溯，不将新ID写入旧编码列。

例如食材原分类为“蔬菜”，字典改名为“蔬果”后，该食材仍显示“蔬菜”；新录入选“蔬果”；主动重新选择才更新该字段。只改数量、日期、图标、食材名，或仅执行用完操作，不刷新未修改的字典快照。编辑接口区分未修改、明确重选和清空。

### 4.4 空值与历史筛选

分类与分区目前在后端新增DTO中均非必填，已整体确认保留可空行为；删空字典后仍可不选该字段录入，不回填默认。旧来源停用/删除后仍可展示历史项，不能因picker索引回退到0而偷偷换选。

新选候选只包含有效启用项；历史筛选从实际有权查看的食材快照生成，包含旧名、停用项和已删来源，同名按名称聚合。快照名变更后形成不同筛选项，不再用个人/家庭重复的旧code跨来源匹配。

## 6. 存量迁移与发布建议

设计阶段不执行SQL。先核对真实库结构、3010/3011模板与个人来源、重复码名、空值、删除数据，以及eat_fridge_food的所属人和编码匹配情况。本地测试数据不能证明生产数据完整。

建议顺序：只读预检 → 备份与相关写入维护窗口 → 增量结构 → 按记录所属人+类型+原code唯一解析来源并冻结迁移时名称 → 初始化家庭模板 → 校验 → 切后端与新端。

迁移时可确定的名称不等于创建时原名；用户已整体确认沿用迁移时唯一可解析名称作为存量基线。缺源、多候选、跨用户来源等异常须停止并输出清单，不能用查看人、当前家庭或任意模板猜测。原本空字段继续为空，已逻辑删除食材也应纳入核查。

校验记录总量、非空快照覆盖、来源可追溯、用户与家庭隔离、历史筛选、两次执行幂等及旧入口阻断。切换覆盖旧包可能仍在运行的窗口：无法表达新来源语义的旧写请求提示重新进入，不猜测转换；不机械复制衣柜专属请求头或新增强制升级页。
